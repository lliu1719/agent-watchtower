WatchTower data path

How telemetry, analysis and containment travel today, given that AI Engine is reachable only through Zscaler ZPA. Updated Oct 21, 2026.

Network diagram

How one detection flows

  1. Agents call models through the gateway. Each department reaches the Chicago gateway over its own Fabric VC, and each agent has its own LiteLLM key.
  2. The gateway reports every call to WatchTower. LiteLLM's OTel callback posts spans to /v1/traces. WatchTower stores them and turns each tool call into an event.
  3. Detectors raise the risk score; the bridge picks up the window. Once risk passes the threshold, WatchTower queues the last 80 events. The laptop bridge is long-polling and takes them.
  4. The bridge invokes AI Engine. It runs on an employee laptop that is on ZPA, with that employee's own AI Engine key.
  5. The verdict comes back to the dashboard. Typical run is about one minute. If no bridge is online, WatchTower shows the last recorded analysis instead.
  6. WatchTower contains. It blocks one agent's key at the gateway, or cuts a Fabric VC when a whole group is involved.
  7. AI Engine notifies people. The Microsoft 365 connector sends Teams or email to the reviewer. Each send needs approval in chat.

GitHub connector: what Lily is checking

The connector runs as the connected user and can only read. Before we design the scenario around GitHub, we need these answers.

  • Can it read comments on issues and PRs, including closed issues?
  • Can it list recent activity in a repo, such as new comments since a given time?
  • Does it see the raw comment body, so hidden HTML comments are visible to the analysis?
  • Which repos it reaches: personal, the org, or private repos the user can see.
  • How long a read takes, and whether there is a rate limit we would hit during a demo.
